界面改版说明
============

这份文档说明 gg-friendly 的界面为什么长成这样，以及各个区域承担什么职责。

目标用户与核心任务
------------------

用户不熟悉 Jujutsu，也不熟悉版本控制的一般概念。打开这个软件时，他脑子里只有三个问题：

1. 现在有什么改动？
2. 哪个改动是我要的？
3. 我想做的事，按哪个按钮？

界面的一切取舍都围绕回答这三个问题展开。术语按日常说法给出，不使用 jj 的行话；
每个改动都有一条完整的中文说明；能点的操作都放在看得见的地方。

只换界面，不换功能
----------------

这次改的是**样子**，不是**本事**。原版 GG 能做的每一件事，改版后都能做；
原版的每一个操作入口，改版后都还在，只是换了个位置或者换了种说法。

具体说：

- 后端的操作（改动、提交、分支、上传下载、撤销重做、拖放改顺序）**一行没动**。
  `app/mutators/` 下的每个 mutator 都和原版一样。
- 改动列表里每一行的**分支标签、标签、工作副本标记**都还是原来那些可拖拽的对象，
  拖动它们的效果和原版一样。分支标签上「和远程断开」的虚线提示也还在。
- 列表工具栏的**查询下拉框、自由输入框、保存查询、删除查询**都还在。
- 改动的**右键菜单、双击编辑、拖放落点、选中行**都还在。
- 泳道图谱用的是原版那套组件，形态和交互都没变。

改掉的只有两处，都是为了让新用户看得懂：

1. **文案** —— 英文和 jj 行话换成日常说法。
2. **布局** —— 从「改动卡片 + 右侧大面板」换成 Git 图形工具常见的三栏结构。

新增的东西有三处：**左边的分支列表**（原来分支信息散落在改动行里，现在
单独立出来，并且点分支能筛选改动列表）、**顶栏的主题三选一**、**分支列表
上的新建分支按钮**。都是往界面上加，没有拿掉原来任何一个入口。

修好的毛病有四处：

1. **右键菜单点了没反应** —— 菜单弹得出来，但一按就没反应。原因是清空
   右键目标的监听器写在捕获阶段，抢在菜单按钮自己的处理之前跑，
   菜单拿到的是空值。现在菜单自己留一份目标，清空动作改到冒泡阶段。
2. **按住 Shift 连选失效** —— 沿同一条历史线连选一段的功能坏了，
   判断父子关系的写法不对，已经按原版的判据改回来。
3. **操作之后列表不刷新** —— 放弃改动、重命名分支、新建分支之后，
   列表要刷新页面才对。现在仓库一变就自动重读。
4. **有些操作之后还是不刷新** —— 复制一个改动之后列表不动。原因是
   「仓库变了没有」这个判断用了状态的内容，而状态里只有工作副本的
   标识；复制改动不动工作副本，状态看着和之前一模一样，刷新信号就没了。
   现在改用一个只增不减的计数器表示「仓库动过」，任何操作成功都加一，
   列表跟着重读。

改完界面后跑一下 `e2e/feature-parity.sh`，它会逐项核对上面这些入口还在不在。

整体结构
--------

界面照着常见的 Git 图形工具（UGit、SourceTree、GitKraken）的样子分四块：

- **顶栏** —— 仓库名、搜索框、上传下载、「新建改动」。上传下载放在顶栏，
  因为这是最常做的两个动作，不该藏在底部的窄条里。
- **左栏：分支列表** —— 仓库里有哪些分支，每个分支什么状态。点一个分支，
  右上角的改动列表就只看这个分支的；再点一次取消。
- **右上：改动列表** —— 一张紧凑的表格，每行一个改动。
- **右下：改动内容** —— 选中改动的文件列表和内容变化并排摆着。

分支列表
--------

从上到下分三组：

- **正在编辑** —— 当前的工作副本。jj 的工作副本是独立的提交，不挂在任何
  分支上，所以没法像 git 那样标「当前分支」，只能单列一条。
- **本地分支** —— 圆点说明状态：橙点=有改动还没上传，绿点=已经和远程一致，
  灰点=这个分支远程上根本没有。
- **远程分支** —— 远程上已经没有的分支会划掉并标「已删除」。

表格
----

改动列表是一张表格，六列：

| 列 | 内容 |
| --- | --- |
| 说明 | 改动的说明文字，最大字号 |
| 作者 | 谁的改动 |
| 时间 | 多久以前 |
| 标识 | 改动的短标识 |
| 分支 | 这个改动在哪些分支上 |
| 状态 | 未上传 / 已上传 / 仅本地 / 有冲突 / 正在编辑 |

没有说明的改动，说明列留空，状态由「状态」列说。分支名和状态分成两列，
不会混在一起看不清哪个是哪个。

选中的一行底色铺满整行，左边还有一条淡蓝竖线。

泳道
----

表格左边是泳道图谱，形态与原版 GG 一致：改动按分支分成若干条竖直的泳道，
每条泳道上一个圆点标出改动的位置，蓝色曲线把改动和它的上一个改动连起来。
分叉时曲线向右分开，合并时收拢回一条泳道。

看这张图就能回答「这个改动是从哪条分支来的」「哪两条分支合到了一起」
「哪些改动还在同一条线上」。

泳道是原版的图谱组件（`GraphLog` / `GraphLine` / `GraphNode`），表格的行
放进图谱预留的位置，两者一起渲染。文字按泳道宽度缩进，不会压到曲线上。
拖动改动时曲线会高亮，松手即完成调整。

状态标记的读法
--------------

- **绿点** —— 正在编辑，这是当前工作副本。
- **红点** —— 改动里有冲突。
- **橙点**（分支列表）—— 这个分支有改动还没上传。
- **深色点** —— 改动已经定稿，不能再直接修改。
- **浅色空心点** —— 普通改动。

定稿的改动要改，需要先用底部的盾牌开关解除保护。

筛选条与标签必须说同一件事
--------------------------

「未上传」「已上传」既是表格里的状态标签，也是筛选条上的筛选项，两者的
判定标准必须一致。这件事靠同一份数据保证：分支列表、表格的状态标签、
筛选条用的分支清单，都从后端的 `query_branches` 来。筛选条按分支名精确
匹配（jj 默认按通配符匹配，`feature*` 会连 `feature-x` 一起选中），所以
筛出来的行正好就是标着对应标签的行。

三个容易混的说法要分清：

- **未上传** —— 分支在远程上有对应分支，但内容不一样，有东西要推上去。
- **已上传** —— 分支在远程上有对应分支，而且两边内容一样。
- **仅本地** —— 远程上根本没有这个分支。

改动列表和分支列表都会跟着仓库的变化自动刷新：新建、重命名、放弃、
复制、撤销、重做之后不用手动刷新。在应用外面改了文件、切回窗口时
也会重新读一遍。

搜索
----

顶栏的搜索框同时搜标题、作者和标识。jj 的匹配规则有两条限制，界面据此分流：

- 标题和作者用通配符匹配，所以搜「chain」能找到标题里含 chain 的所有改动。
- 标识只接受前缀，而且改动标识的字母表只有 k 到 z，提交标识是十六进制。
  所以看起来像改动标识的词走标识匹配，像提交标识的走提交标识匹配，
  其余的只匹配标题和作者。

搜不到东西时显示「没有符合条件的改动」，并提示可以换筛选条件或清空搜索词。

术语对照
--------

界面用日常说法，jj 的说法记在这里，方便对照官方文档：

| 界面说法 | jj 术语 |
| --- | --- |
| 改动 | revision / commit |
| 工作副本 | working copy |
| 上一个改动 | parent |
| 分支 | bookmark |
| 远程分支 | remote bookmark |
| 标签 | tag |
| 改动内容 | change |
| 冲突 | conflict |
| 已定稿 | immutable |
| 合并到上一个改动 | squash into parent |
| 从上一个改动恢复 | restore from parent |
| 放弃这个改动 | abandon |
| 编辑这个改动 | edit as working copy |
| 新建子改动 | new child |
| 开始跟踪远程分支 / 停止跟踪远程分支 | track / untrack |
| 上传 / 下载 | push / fetch |
| 复制一份 | duplicate |
| 未上传 / 已上传 / 仅本地 | ahead / synced / local-only |

配色与主题
----------

沿用 Catppuccin 配色，浅色下用 Latte，深色下用 Macchiato。

主题有三个选项，在顶栏右上角切换：

- **跟随系统** —— 跟着操作系统的设置走，也是默认选项。
- **浅色** —— 一直用 Latte。
- **深色** —— 一直用 Macchiato。

选中的那一个会记在本地，下次打开还在。

仓库自己在配置文件里写的 `gg.ui.theme-override` 仍然有效，但顶栏的选择
优先于它。

标识有各自的颜色：改动标识粉色，提交标识紫色。两者同屏出现时，靠颜色就能分清。
这个颜色在两种主题下分别调暗和调亮，保证对比度都够。

字与行
------

正文用系统中文无衬线字体（PingFang SC / 微软雅黑 / Noto Sans CJK SC），
标识和文件路径用等宽字体。正文 14 到 15 像素，元信息 12.5 像素，
标签 11.5 像素。中文正文行高 1.45 到 1.7。

控件的样子
----------

整个界面只有一套控件样式，**以顶栏为准**。顶栏是最干净、最克制的一处，
其它地方都向它看齐：

- 圆角 8 像素，小标签 6 像素。不用胶囊形。
- 描边 1 像素，颜色比底色深一档。
- 底色用面板底色（`--ctp-base`），不是更深的背景色。
- 按钮高 34 像素，小控件 28 像素；字号 13.5 像素，小控件 12.5 像素。
- 按钮里带图标，图标 16 像素。
- 主要动作是实心蓝底（`--ctp-blue`），次要动作是浅底深字。
- 悬停只换底色，不位移；按下不陷进去。
- 焦点用 2 像素的淡紫描边。

这些数字都写成了全局变量（`app/global.css` 里的 `--radius-control`、
`--height-control`、`--size-control-text` 等），各处引用同一份，
改一处就整体跟着变。

右上角的主题切换是一个小分组，用淡紫底表示当前选中的那个。

原版那套「立体按钮」（硬阴影、按下去会陷进去、凸字字体）已经全部换掉，
不再出现在界面上的任何地方。
